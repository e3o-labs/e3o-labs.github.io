# TRIP119 원페이지 개편 계획

작성일: 2026-09-28

## 목표

기존 TRIP119 소개·지원 페이지를 제품을 처음 보는 사람도 이해할 수 있는 원페이지 소개로 개편한다.

지원 정보와 개인정보 안내는 유지하면서, 현재 기능과 앞으로 준비하는 기능을 한눈에 볼 수 있게 한다.

## 이번 작업 범위

### 1. 첫 화면

- TRIP119 이름과 한 줄 설명
- "여행이 흔들릴 때, 사람부터 다시 살립니다." 메시지
- iPhone 제공 상태
- 지원 안내로 이동하는 링크

### 2. 지금 할 수 있는 일

현재 앱에서 실제로 제공하는 흐름을 짧게 설명한다.

- 여행 지역 선택
- 상황과 조건에 맞는 후보 확인
- 일정에 장소 추가·변경·제외
- 여행 중 다시 후보 찾기
- 전국 지역 선택
- 공식 관광정보를 확인할 수 있는 후보 제공

### 3. 실제 앱 이미지

TRIP119 저장소에 있는 브랜드·앱 이미지 자산을 우선 사용한다.

웹페이지용으로 재사용하기 어려운 자산만 별도 내보내기 또는 캡처를 준비한다. 실제 앱과 다른 가짜 화면을 홍보 이미지처럼 사용하지 않는다.

### 4. 다음 업데이트

현재 출고 계획에 포함된 내용을 일반 사용자 언어로 소개한다.

- 저장한 여행 기록
- 현재 여행 식별 개선
- 현재 여행을 바꾸지 않는 독립적인 긴급 여행지 추천

내부 Build 번호는 노출하지 않는다.

### 5. 앞으로 준비하는 기능

출시 약속이 아니라 방향을 보여주는 영역으로 둔다.

- 방문 완료와 선택 후기
- Journey Graph
- 지도 표시
- 지도와 여행 변경이력 연결
- 위치 검색과 이동시간을 활용한 추천 개선

### 6. 플랫폼

- iPhone: 제공 중
- Android: 준비 중
- Web: 준비 중

Android/Web의 구체적인 구현 방식과 출시일은 확정 전까지 쓰지 않는다.

### 7. 문의

현재는 이메일 문의를 그대로 유지한다.

동시에 "문의폼 준비 중"을 표시한다.

Google Forms URL이 확정되면 문의 버튼을 폼으로 바꾸고 이메일 주소는 제거한다.

## 디자인 원칙

- 모바일에서 먼저 읽히는 구성
- 앱의 현재 색과 분위기를 기준으로 사용
- 카드가 너무 많아 제품 설명이 조각나지 않게 한다
- 긴 문단보다 짧은 설명과 실제 화면을 우선한다
- 로드맵은 제품 설명보다 아래에 둔다
- "준비 중" 기능은 현재 기능과 시각적으로 구분한다

## 완료 조건

- 현재 기능과 예정 기능이 섞이지 않는다.
- iPhone, Android, Web 상태가 명확하다.
- 이메일 문의와 문의폼 준비 중 상태가 함께 보인다.
- 개인정보 처리 안내로 이동할 수 있다.
- 모바일과 데스크톱에서 내용이 깨지지 않는다.
- 저장소의 현재 계획과 공개 문구가 충돌하지 않는다.
